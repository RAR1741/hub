## Purpose

Cheesy Hours is a project-hour and attendance tracking web app built by FRC Team 254 for the Bellarmine Robotics Lab. Students sign in on a kiosk at the lab door using their student ID, but cannot sign themselves out; a mentor signs them out either through the web UI or by texting the student's ID to a Twilio phone number. On top of that raw sign-in/sign-out ledger, the app computes total "project hours," a public leaderboard, and a per-build-day attendance calendar that distinguishes required from optional build days and tracks excused absences. Its users are students (sign in, view leaderboard, view their own attendance), mentors (sign students out, check themselves in), and admins/leads (edit sessions, manage the build-day calendar, run CSV reports, sync the roster).

## Stack

- **Language:** Ruby. `.ruby-version` pins **2.7.1**, while `README.md` states the team runs 2.3.0 — the two disagree.
- **Framework:** Sinatra (`Sinatra::Base`, modular style) — the entire HTTP layer is one file, `hours_server.rb`. Served by **Thin**, daemonized with **Daemons** via `hours_server_control.rb`.
- **Database:** MySQL 5.6 (`mysql2`) accessed through the **Sequel** ORM. Connection built in `db.rb`; migrations in `db/migrations/`, run by the `db:migrate` Rake task in `Rakefile`.
- **Key libraries:** `sequel`, `sinatra`, `thin`, `mysql2`, `daemons`, `activesupport` (time zones), `tzinfo-data`, `httparty`, `pathological` (load-path management, `Pathfile`), and `cheesy-common` — a Team 254 gem pulled directly from GitHub (`Gemfile`, `Gemfile.lock`) that supplies SSO auth, config loading, and AES-encrypted config values.
- **Frontend:** Server-rendered ERB templates in `views/` with a shared `views/header.erb` / `views/footer.erb`. Bootstrap 2.x and jQuery 1.10.1 are vendored in `public/js/` and `public/css/bootstrap.min.css`; custom styling and CSS variables for the calendar color scheme live in `public/css/css.css`. Sprinkles of inline jQuery for polling and scroll-syncing; no build step, no JS framework.
- **License:** **No LICENSE file exists in the repo.** Source headers read `Copyright 2013 Team 254. All Rights Reserved.` — the code is publicly readable but carries no open-source grant.
- **Deployment:** Self-hosted, no Docker and no Heroku. The `deploy` bash script SSHes to `team254@ec2.team254.com`, then in `/opt/sites/cheesy-hours` runs `git checkout master && git pull && bundle install && bundle exec rake db:migrate && bundle exec ruby hours_server_control.rb restart`. Environment-specific settings (dev/prod DB credentials, port 9006, IP whitelist, members URL) come from `config.json`. `README.md` describes optional nginx reverse-proxying in front of the Ruby process.

## Auth & Roles

Sign-in is delegated to Team 254's custom SSO ("members" site). A Sinatra `before` filter in `hours_server.rb` calls `CheesyCommon::Auth.get_user(request)`; if no user is found, the request is redirected to `CheesyCommon::Config.members_url?site=hours&path=<path>`. The user object is cached in a `Rack::Session::Cookie` session with a 3600-second expiry. `/logout` clears the session and bounces to the SSO logout endpoint.

Four routes are exempt from the auth redirect: `/`, `/sms`, `/signin_internal`, and `/signout_automatic`. Two local-development bypasses exist: `DISABLE_AUTH=1` injects a `DevUser` struct whose `has_permission?` always returns true, and `HOURS_BYPASS_AUTH=1` constructs a `CheesyCommon::User` with a fixed permission set; both accept `HOURS_BYPASS_BCP_ID` to choose the impersonated student ID (default `900001`).

Authorization is permission-string based, checked inline per route with `@user.has_permission?(...)`:

- `HOURS_SIGN_IN` — use the kiosk sign-in form / `POST /signin`.
- `HOURS_EDIT` — the bulk of admin actions: sign students out, create/edit lab sessions, excusals, build-day scheduling, mentor CRUD, mentor check-ins, calendar, search, suspect-session review.
- `HOURS_DELETE` — delete lab sessions.
- `HOURS_VIEW_REPORT` — download the two CSV reports.
- `DATABASE_ADMIN` — `/reindex_students`, `/reset_hours`, and deleting an entire build day.
- `EVENTS_SIGNUP_EVENT` — not a permission this app checks for access; it is the filter used against the SSO directory to decide who counts as a student during roster sync.

The README notes both the auth and the authorization layers are Team-254-specific and would need replacement, suggesting a hard-coded user/permission list as the simplest substitute.

## Data Model

- **Student** (`models/student.rb`, `db/migrations/001_create_students.rb`) — primary key is the school's six-digit student ID (unrestricted PK, not auto-assigned); `first_name`, `last_name`. `has_many` lab_sessions and excused_sessions. Computes `project_hours`, `week_hours(week)`, and `total_sessions_attended` in Ruby.
- **LabSession** (`models/lab_session.rb`, migrations 002/004/005/007) — `student_id`, `time_in`, `time_out` (nil = currently signed in), `mentor_id`, `mentor_name` (free-text fallback for who signed the student out), `notes`, `excluded_from_total` boolean. `belongs_to` student and mentor; `duration_hours` derived from the time range.
- **Mentor** (`models/mentor.rb`, migration 003) — `first_name`, `last_name`, `phone_number` (whitelist for SMS sign-out). `has_many` lab_sessions.
- **MentorCheckin** (`models/mentor_checkin.rb`, migration 006) — `mentor_id`, `time_in`; recorded for contact tracing.
- **OptionalBuild** (`models/optional_build.rb`, migration 008) — a unique `date` marking a day as optional; auto-created on sign-in for non-required weekdays.
- **ScheduledBuildDay** (`models/scheduled_build_day.rb`, migration 010) — unique `date` plus `optional` boolean; an explicit, higher-priority override of a day's required/optional status.
- **ExcusedSession** (`models/excused_session.rb`, migration 009) — `date` + `student_id`, with validations that both be present; excuses a student from a required day.

The "build day" concept is not a first-class table: `queries.rb` derives the set of build days as the UNION of distinct sign-in dates, optional-build dates, and scheduled-build-day dates, then resolves required-vs-optional through a precedence CASE (scheduled_build_days → optional_builds → `REQUIRED_BUILD_DAYS` weekday list → optional).

## Features

- **Kiosk sign-in** — Landing page shows a large autofocus student-ID field (barcode-scanner friendly, submit button id `scanSubmit`) that opens a lab session; rejects unknown IDs, duplicate open sessions, and requests from outside the configured IP whitelist. `hours_server.rb` (`get "/"`, `post "/signin"`), `views/index.erb`, `models/student.rb`, `config.json` (`signin_ip_whitelist`).
- **Internal sign-in API** — `POST /signin_internal` performs the same sign-in without auth or IP checks, and is excluded from the auth redirect; it is intended to be reachable only from localhost, giving other on-box software a hook to sign students in. `hours_server.rb`.
- **Live "currently signed in" board** — Table of open sessions with time-in, refreshed by a jQuery poll every 120 seconds; anonymous viewers see only student IDs while logged-in viewers see names, and privileged viewers get inline Sign Out / Delete buttons. `hours_server.rb` (`get "/lab_sessions/open"`), `views/signed_in_list.erb`, `views/index.erb`.
- **SMS sign-out (single and batch)** — Mentors text one or more student IDs (full six digits or just the last four, space-separated) to the Twilio number; each is signed out and the reply reports the hours logged or an error per ID. `hours_server.rb` (`post "/sms"`, `sms_response`), `models/student.rb`, `models/mentor.rb`.
- **SMS mass sign-out ("GTFO")** — A message of `gtfo` closes every open lab session at once, crediting the texting mentor. `hours_server.rb` (`post "/sms"`).
- **SMS mentor check-in ("HERE")** — A message of `here` records a `MentorCheckin` row for the sender, used for contact tracing. `hours_server.rb`, `models/mentor_checkin.rb`.
- **Web sign-out** — One-click sign-out from the signed-in list, stamping the current time and the acting user's display name. `hours_server.rb` (`get "/lab_sessions/:id/sign_out"`), `views/signed_in_list.erb`.
- **Leaderboard** — All students ranked by total project hours, with session counts and links to individual student pages, plus a CSV download link for report viewers. `hours_server.rb` (`get "/leader_board"`), `views/leader_board.erb`, `models/student.rb`.
- **Student detail page** — Per-student list of every lab session (time in/out, hours, who signed them out, excluded flag, notes) plus, for editors, an excusals table and buttons to add sessions/excusals. `hours_server.rb` (`get "/students/:id"`), `views/student.erb`.
- **My Attendance** — Self-service page for the logged-in user resolved by SSO id, showing a semester summary (builds attended, required builds, required attended, attendance rate, unexcused absences) and a date-by-date Present/Excused/Optional/Absent table, with semester and year selectors. `hours_server.rb` (`get "/my_attendance"`), `views/my_attendance.erb`, `queries.rb` (`STUDENT_ATTENDANCE_RANGE_QUERY`, `BUILD_DAYS_RANGE_QUERY`).
- **Manual lab session creation** — Editors can add a session for a student with arbitrary time in/out and notes, optionally prefilled from a `?date=` parameter when launched from a calendar cell. `hours_server.rb` (`get/post "/students/:id/new_lab_session"`), `views/edit_lab_session.erb`.
- **Lab session editing** — Change time in/out, notes, and the "excluded from total" flag; mentor attribution is set or cleared automatically depending on whether a time-out was added or removed. `hours_server.rb` (`get/post "/lab_sessions/:id/edit"`), `views/edit_lab_session.erb`.
- **Lab session deletion** — Confirmation-page-gated delete requiring `HOURS_DELETE`. `hours_server.rb` (`get/post "/lab_sessions/:id/delete"`), `views/delete_lab_session.erb`.
- **Excuse a student for a date** — Records an excused absence so the student is not penalized for missing a required build; reachable from the student page or directly from a red calendar cell. `hours_server.rb` (`get/post "/students/:id/mark_excused"`), `views/mark_excused.erb`.
- **Remove an excusal** — Deletes an excused-session row, from either the student page or the calendar's "Unexcuse" menu item. `hours_server.rb` (`get/post "/students/:id/excusals/:date/delete"`), `views/delete_excusal.erb`.
- **Attendance calendar grid** — Wide, transposed grid of students (rows, ordered by builds attended) against build days (columns), color-coded absent/present/optional/excused with a legend, semester + year pickers, a "hide optional builds" filter, per-student attendance rate and unexcused-absence count, sticky synchronized header/body horizontal scrolling, and a hover dropdown on every cell offering the contextually relevant action (edit/delete session, add session, excuse, unexcuse). `hours_server.rb` (`get "/calendar"`), `views/calendar.erb`, `queries.rb` (`CALENDAR_BUILD_INFO_RANGE_QUERY`, `CALENDAR_STUDENT_INFO_RANGE_QUERY`, `BUILD_DAYS_RANGE_QUERY`), `public/css/css.css`.
- **Schedule a build day** — Explicitly create or update a dated build day as required or optional, so it appears on the calendar even before anyone signs in. `hours_server.rb` (`get/post "/schedule_build_day"`), `views/schedule_build_day.erb`, `models/scheduled_build_day.rb`.
- **Mark a build day optional** — Dedicated flow (also linked per column from the calendar header) that flags a date optional: attendance still earns credit but absence is not penalized. `hours_server.rb` (`get/post "/schedule_optional"`), `views/optional_build_scheduler.erb`, `models/optional_build.rb`.
- **Mark a build day required** — Inverse action, removing the optional flag for a date. `hours_server.rb` (`get/post "/delete_optional/:date"`), `views/delete_optional_build.erb`.
- **Delete a build day** — `DATABASE_ADMIN`-only removal of a date from the calendar: clears its optional/scheduled/excused rows and marks every lab session that started that day as `excluded_from_total`. `hours_server.rb` (`get/post "/build_days/:date/delete"`), `views/delete_build_day.erb`.
- **Optionalize past off-days (bulk)** — One confirmation click marks every past date that falls outside `REQUIRED_BUILD_DAYS` and had at least one sign-in as optional; the confirmation text enumerates the affected weekdays. `hours_server.rb` (`get/post "/optionalize_past_offdays"`), `views/optionalize_past_offdays.erb`, `constants.rb`, `queries.rb` (`BUILD_DAYS_QUERY`).
- **Mentor management** — List mentors with phone numbers, add a mentor (phone normalized to its last ten digits, which whitelists them for SMS sign-out), and delete a mentor behind a confirmation page. `hours_server.rb` (`get "/mentors"`, `post "/mentors"`, `get "/new_mentor"`, `get/post "/mentors/:id/delete"`), `views/mentors.erb`, `views/new_mentor.erb`, `views/delete_mentor.erb`.
- **Mentor check-in log** — Reverse-chronological list of mentor lab check-ins (created by the "here" SMS) with per-row delete. `hours_server.rb` (`get "/mentor_checkins"`, `get/post "/mentor_checkins/:id/delete"`), `views/mentor_checkins.erb`, `views/delete_mentor_checkin.erb`.
- **Suspect lab sessions report** — Lists non-excluded sessions longer than 18 hours, sorted longest first, with inline edit/delete so implausible sessions (e.g. forgotten sign-outs) can be corrected. `hours_server.rb` (`get "/suspect_lab_sessions"`), `views/suspect_lab_sessions.erb`.
- **Date-range session search** — Search closed lab sessions overlapping a start/end date range (end optional for a single day), returning student, times, hours, signer, and notes. `hours_server.rb` (`get/post "/search"`), `views/search.erb`.
- **Hours CSV export** — Downloadable CSV of last name, first name, student ID, project hours, and total sign-outs for every student. `hours_server.rb` (`get "/csv_report"`), linked from `views/leader_board.erb`.
- **Attendance CSV export** — Second CSV adding an attendance-percentage column computed from the build-day query. `hours_server.rb` (`get "/csv_attendance_report"`), `queries.rb` (`CALENDAR_STUDENT_INFO_QUERY`), linked from `views/calendar.erb`.
- **Roster sync from SSO** — Admin endpoint that pulls all SSO users holding `EVENTS_SIGNUP_EVENT`, inserts or updates their `students` rows, and deletes any student not present in the pull. `hours_server.rb` (`get "/reindex_students"`).
- **Season hours reset** — Admin endpoint that bulk-deletes lab sessions whose time-out predates a hard-coded 2018-01-06 cutoff. `hours_server.rb` (`get "/reset_hours"`).
- **Automatic sign-out sweep** — Unauthenticated, internal-only endpoint that closes all open sessions with the mentor name "Automatic - Didn't Sign Out" at a configurable time offset; intended to be triggered on a schedule. `hours_server.rb` (`get "/signout_automatic"`), `config.json` (`automatic_signout_offset_hours`).
- **Logout** — Clears the local session and redirects to the SSO logout page. `hours_server.rb` (`get "/logout"`), `views/header.erb`.
- **Role-aware navigation** — The shared navbar conditionally exposes Leader Board, My Attendance, Calendar, and an Admin dropdown (Manage Mentors, Mentor Check-ins, Schedule Build Day, Schedule an Optional Build, Review Suspect Lab Sessions, Search) plus a user menu or Login link. `views/header.erb`.

## Integrations

- **Twilio SMS** — `POST /sms` in `hours_server.rb` is the Twilio messaging webhook. It reads `params[:From]` and `params[:Body]`, and hand-builds a TwiML `<Response><Sms>…</Sms></Response>` payload in the `sms_response` helper (HTML-escaping each message) rather than using a Twilio SDK. Outbound messaging is entirely Twilio's reply-to-webhook mechanism; there is no API client and no credentials in the repo. `README.md` documents the Twilio console configuration and the ~$1/month + $0.01/message cost.
- **Team 254 SSO / members site** — Authentication, the permission model, and the student roster all come from the `cheesy-common` gem sourced from `https://github.com/Team254/cheesy-common.git` (`Gemfile`, `Gemfile.lock`), used in `hours_server.rb` (`CheesyCommon::Auth.get_user`, `CheesyCommon::Auth.find_users_with_permission`), `db.rb`, and `views/header.erb` (`CheesyCommon::Config.members_url`). That gem also handles the `Encrypted:` config values in `config.json` via `aescrypt` and brings in `httparty` for its HTTP calls.
- **Barcode / ID scanners** — Not a software integration, but the sign-in form is built around scanner input (autofocus numeric field, immediate submit); see `views/index.erb`.
- **CDN-hosted assets** — Google Fonts (`Open Sans`) imported in `public/css/css.css`, and favicons/Apple touch icons loaded from `media.team254.com` in `views/header.erb`.
- No email provider, Slack, Google Sheets, calendar sync, or push-notification integration exists anywhere in the codebase.

## Notable Implementation Details

- **Single-file router, no tests.** All ~40 routes live in `hours_server.rb` (~625 lines); there is no test directory, CI config, or linter.
- **Raw SQL in views.** `views/calendar.erb` and `views/my_attendance.erb` call `DB.fetch` with the CTE-heavy queries from `queries.rb` directly during rendering, and each first executes `SET sql_mode=(SELECT REPLACE(@@sql_mode,'ONLY_FULL_GROUP_BY',''))` to relax MySQL's grouping strictness at render time. `views/leader_board.erb`, `views/mentors.erb`, and `views/suspect_lab_sessions.erb` likewise query models inline.
- **Hard-coded database name.** Every table reference in `queries.rb` is prefixed `cheesy_frc_hours.`, so changing `db_database` in `config.json` alone will not work — the SQL must be edited too.
- **Build days are derived, not stored.** Required/optional status resolves through the `optional_build_case` CASE in `queries.rb`: an explicit `scheduled_build_days.optional` wins, then presence in `optional_builds` means optional, then the weekday is checked against `REQUIRED_BUILD_DAYS`, else optional. The four range-scoped query variants take `(start, end, hide_optional)` positional parameters.
- **Optional builds are created as a side effect of sign-in.** `POST /signin` checks whether today's weekday is outside `REQUIRED_BUILD_DAYS` and, if no `optional_builds`/`scheduled_build_days` row exists, creates one — so simply opening the lab on a Tuesday silently registers a new optional build day.
- **Attendance math.** Required-build denominators count a day only if the student was not excused or was excused and still attended (`queries.rb`), so excusals shrink the denominator rather than counting as attendance. Sessions flagged `excluded_from_total` are omitted from hours, session counts, and build-day derivation everywhere.
- **Last-four-digit ID shortcut.** `Student.get_by_id` in `models/student.rb` first tries the full ID as the primary key, then falls back to `MOD(id, 10000) = <input>` — a full table scan against a function, and a collision risk for ID schemes where the last four digits are not unique. `README.md` flags this as the place to change for other schools.
- **Phone number normalization.** Both mentor creation and inbound SMS strip non-digits and keep the last ten characters (`hours_server.rb`), so matching is US-10-digit-centric.
- **IP whitelisting keys off `X-Real-IP`.** `POST /signin` compares `request.env["HTTP_X_REAL_IP"]` with prefix matching against `signin_ip_whitelist`; an empty whitelist disables the check. This assumes a trusted reverse proxy is setting that header.
- **Internal-only endpoint detection is inverted-proxy-based.** `/signout_automatic` halts if `HTTP_X_REAL_IP` is *present*, i.e. it only accepts requests that did not pass through nginx — the mechanism by which a localhost cron job (or equivalent scheduler; the repo ships no crontab or job definition) is distinguished from public traffic. `automatic_signout_offset_hours` is `-2` in `config.json`, so auto-closed sessions are backdated two hours instead of credited to the moment the sweep runs.
- **Timezone handling.** `constants.rb` fixes `USER_TIME_ZONE` to `America/Los_Angeles` and `REQUIRED_BUILD_DAYS` to Monday/Wednesday/Friday/Saturday as load-time constants; times are stored UTC and rendered via ActiveSupport `in_time_zone`. `parse_user_time` interprets form input in the user zone, `POST /search` parses each endpoint separately so DST offsets are correct per date, and `views/edit_lab_session.erb` appends the browser's UTC offset to typed timestamps with an `onchange` handler.
- **Open-redirect guard.** The `safe_referrer` helper normalizes backslashes and only honors a `referrer` parameter that starts with a single `/`; most admin forms round-trip `request.referrer` through a hidden field so confirmation pages return the user to where they came from.
- **Transposed HTML table.** The calendar renders students as `<tr>` elements displayed as table cells via `table.column-based` CSS rules in `public/css/css.css`, with a `rowNum.modulo(studentsCnt)` counter in `views/calendar.erb` deciding where rows break — the grid's correctness depends on the SQL returning exactly one row per (day, student) pair in a stable order. Two panes are scroll-synced by jQuery, and the last two columns' dropdowns get `pull-right` applied so menus do not clip.
- **Hard-coded thresholds.** The suspect-session cutoff is `duration_hours > 18` inside `views/suspect_lab_sessions.erb`, and `/reset_hours` embeds the date `2018-01-06`; neither is configurable.
- **Semester windows are fixed calendar ranges** (Fall = Aug 1–Dec 31, Spring = Jan 1–May 31, Summer = Jun 1–Jul 31), duplicated in both `get "/calendar"` and `get "/my_attendance"` in `hours_server.rb`.
- **Hours are computed in Ruby, not SQL.** `project_hours`, `week_hours`, and `total_sessions_attended` iterate the association in `models/student.rb`, and the leaderboard sorts all students in memory (with `eager(:lab_sessions)` to blunt the N+1), which ties page cost to total session volume.
- **Config secrets.** `config.json` is committed, with a plaintext dev DB password and an `Encrypted:`-prefixed production password decrypted by `cheesy-common`; `README.md` notes plaintext is also accepted.
- **Deployment assumptions.** Deploy is a push-button SSH script against one EC2 host with the repo checked out in place and migrations run on every deploy; the process is a `Daemons`-monitored Thin server on port 9006, expected to sit behind nginx (or be reconfigured to bind 80). There is no Dockerfile, Procfile, or process manager config beyond `hours_server_control.rb`.
