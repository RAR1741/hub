## Purpose

GatherPack is a self-hostable Rails web application for managing an organization of people — originally built for a FIRST Robotics Competition team that had outgrown spreadsheets, and generalized for other groups. It centralizes a member roster with personal details, a hierarchical tree of teams/subteams, event attendance check-ins, time-clock hours, badges/credentials, RFID tokens, financial ledgers and budgets, announcements and digests, inbound email mailboxes, a team Q&A board, and a CMS. Its users are members (who view their own dashboard, join teams, punch in at a kiosk, check in to events), team managers (who administer their subtree's people, events, hours, and finances), and admins/architects (who configure the site, run reports, define hooks, and audit changes).

## Stack

- **Language/runtime:** Ruby 4.0.2 (`.ruby-version`, `Dockerfile`), Node 20.18 + Yarn 1.22 for CSS build only (`.node-version`, `package.json`).
- **Framework:** Rails ~8.1 monolith (`Gemfile`, `config/application.rb`), Puma 8 + Thruster.
- **Database:** PostgreSQL 16, **two databases** — `primary` plus a separate `versions` database holding PaperTrail audit records with its own migration path (`config/database.yml`, `db/schema.rb`, `db/versions_schema.rb`, `db/versions_migrate/`, `app/models/abstract_version.rb`). UUID primary keys throughout (`config/application.rb` generators block).
- **Backing services:** Solid Queue (jobs), Solid Cache, Solid Cable — all database-backed, no Redis (`config/queue.yml`, `config/solid_cache.yml`, `config/cable.yml`). Mission Control Jobs UI.
- **Key libraries:** Devise 5 (auth) + OmniAuth 2 (Google/Discord/GitHub/developer), Doorkeeper (OAuth2 provider), Pundit (authorization), Ransack 4 (search/filter), Kaminari (pagination), SimpleForm 5 + custom inputs, Gretel (breadcrumbs), PaperTrail 17 (auditing), money/money-rails (currency), `neat_ids` (prefixed human-readable IDs over UUIDs), `pretender` (impersonation), Redcarpet (Markdown), Stripe 19, `postmark-rails`, `pstore` (settings), `spicy-proton` (passphrase generation), `hotwire_combobox`, `color`, `pmap`, `herb`.
- **Frontend:** Server-rendered ERB + Hotwire (Turbo Drive/Frames/Streams + Stimulus), Bootstrap 5.3 compiled from SCSS via `sass` + `postcss`/`autoprefixer`. JS via `importmap-rails` with **no bundler**; CodeMirror 6 and FullCalendar 6 vendored as ESM in `vendor/javascript/`. Trix + ActionText, FontAwesome 7 and Google Fonts from CDN. PWA manifest + service worker stub.
- **License:** MIT, Copyright (c) 2024 Brad Thompson (`LICENSE.txt`).
- **Deployment:** Self-hosted Docker. Production `Dockerfile` (multi-stage, non-root), `docker-compose-app.yml` for a production-ish stack, `docker-compose.yml` for dev Postgres + mailcatcher, Kamal config (`config/deploy.yml`), `Procfile` (web + solid_queue worker), devcontainer. `storage/` must be a writable persistent volume because runtime settings live in a PStore file there. CI on GitHub Actions: brakeman, importmap audit, rubocop, tests + system tests (`.github/workflows/ci.yml`).

## Auth & Roles

Sign-in is Devise-based with `database_authenticatable`, `registerable`, `recoverable`, `rememberable`, `validatable`, `omniauthable` (`app/models/user.rb`). Local email/password login and local self-signup are each independently toggleable via runtime settings (`local_auth`, `local_signup`). OmniAuth providers (Google, Discord, GitHub, plus a `developer` provider in development) are registered in `config/initializers/devise.rb` only when their client ID/secret settings are present; callbacks land in `app/controllers/omniauth_controller.rb` and `User.create_from_provider_data` either creates an account (when `oauth_signup` is enabled) or links the provider to an existing email. The **first user created is automatically promoted to admin** (`User#adminify_first_user`). Password resets and other Devise mails are sent through a gateway rather than ActionMailer (`app/mailers/devise_gateway_mailer.rb`).

`User` carries only two boolean role flags — `admin` and `architect` — while all human data lives on `Person`. Manager status is derived, not stored: `Person#manager?` is true if the user is an admin or holds any `Membership` with `manager: true`. `ApplicationController#check_for_user` requires a session for every non-Devise request, so essentially the whole app including the kiosk sits behind login; the only skips are the gateway webhook action and the OAuth userinfo endpoint.

Fine-grained authorization is Pundit, one policy per model in `app/policies/`. Policy scopes implement the team-tree visibility rules (e.g. `PersonPolicy::Scope` limits people to those sharing a team; `TimeClockPunchPolicy::Scope` limits to self or managed teams). Beyond roles, several models carry their own permission enums: `Team#join_permission` (`added_by_admin`, `added_by_manager`, `added_by_current_member`, `has_account`, `requires_approval`), `Badge#permission` (6 levels including `*_or_self`), `CheckinField#permission`, `TimeClockPeriod#permission`, `RelationshipType#permission`, and `Page#viewer`/`Page#editor` (`public`/`user`/`team`/`manager`/`admin`). Admins can impersonate any user via `pretender`, and PaperTrail records the true (non-impersonated) user as `whodunnit`.

## Data Model

- **User** — authentication only (email, encrypted password, provider/uid, `admin`, `architect`). `has_one :person`.
- **Person** — the hub entity: names/display name, gender, shirt size, phone, address, birthday, dietary restrictions, bio, attached avatar; optional `user_id`. Has many memberships/teams, badge assignments/badges, checkins/events, tokens (polymorphic), ledger ownerships, time clock punches, calendar notes, membership applications.
- **Team** / **TeamType** — self-referential tree (`parent_id`) typed by `TeamType` (icon, `manager_title`). Owns announcements, badges, events, pages, time clock periods, ledgers, budget periods, shortcuts, calendar notes, questions. `Membership` (person↔team, `manager` flag) is the join; `MembershipApplication` (pending/approved/denied) is the approval queue.
- **Relationship** / **RelationshipType** — typed parent/child links between two `Person` records with directional labels.
- **Badge** / **BadgeType** / **BadgeAssignment** — badges belong to a type and optionally a team; assignments join badge↔person.
- **Token** — polymorphic `tokenable` (Person or Hook) holding an RFID/access value.
- **Event** / **EventType** / **Checkin** / **CheckinField** / **CheckinFieldResponse** — events belong to a type and optionally a team and a time clock period; check-ins join person↔event and carry one response per checkin field defined on the event's type.
- **TimeClockPeriod** / **TimeClockPunch** — periods scope punches to a date range, optional team, and permission level; punches record person, start/end, note.
- **Ledger** / **LedgerEntry** / **LedgerOwnership** / **LedgerTag** / **LedgerTagging** / **LedgerEntryLink** / **LedgerEntryLinking** — one or more ledgers per team with a cached `balance_cents`; entries are monetized, polymorphically `created_by`, self-referential for splits (`parent_id`), flagged `finalized`/`approved`/`failed`/`transfer_mirror`, carry `jsonb` metadata and attached receipts, are tagged, and are grouped across ledgers via links (used for transfers). Ownership is polymorphic (Person or Team).
- **BudgetPeriod** / **Budget** / **BudgetTagging** — a period per team; each budget is an amount matched against ledger entries carrying *all* of its tags.
- **Announcement** — title/content, start/end window, optional team. **Shortcut** — named/iconed/colored link scoped to a team. **CalendarNote** — polymorphic dated note. **Page** — CMS content with `viewer`/`editor` permission levels and a `dynamic` ERB flag.
- **Question** / **Reply** / **ReplyVote** — team-scoped questions with threaded replies and one vote per person per question.
- **Gateway** (STI: `Gateway::StripeGateway`, `Gateway::PostmarkSendingGateway`, `Gateway::PostmarkReceivingGateway`) — `jsonb` configuration. **Mailbox** / **MailboxMessage** / **MailboxAssignment** — an inbound address, its messages (with attachments), and polymorphic targets.
- **Theme** (singleton: CSS variables, custom CSS, PWA colors, logo), **Variable** (typed key/value), **Report** (named Ruby snippet), **Hook** (event name + Ruby snippet), **AuditLog** (PaperTrail version in the separate DB), **OauthApplication** (Doorkeeper).
- Non-persisted form/service models: `TimeKiosk`, `LedgerPayment`, `LedgerTransfer`, `Infodump`, `RelationshipNode`.

## Notable Implementation Details

- **Settings live in a PStore file, not the database or ENV.** `lib/settings.rb` wraps `storage/settings.pstore`; `config/routes.rb` branches on settings when *defining* routes and `config/initializers/devise.rb` reads OAuth credentials at boot — so toggling a feature or adding OAuth credentials requires a restart. Booleans are stored as strings `"true"`/`"false"`.
- **Feature/plugin architecture.** `GatherPack::Feature` objects declare key, label, default state, nav/setup items, optional `routes_proc`; registered in `config/initializers/features.rb` inside `config.to_prepare`. The `Gemfile` `instance_eval`s an optional `Pluginfile`; the intended plugin path is a gem registering its own Feature from a Railtie. The `routes_proc` wiring is currently commented out.
- **Orphaned schema tables imply out-of-tree plugins.** `db/schema.rb` contains `accounts`, `transactions`, `operations`, `lego_lottery_*` tables with no corresponding app code in this repo.
- **`neat_ids` + a `method_missing` bridge.** UUID PKs with prefixed display IDs (`per_…`, `tm_…`); `ApplicationRecord#method_missing` synthesizes `*_nid` readers/writers that resolve a neat ID to a record — how combobox inputs submit polymorphic references.
- **Two-database PaperTrail.** Audit history is in a physically separate PostgreSQL database with its own migrations (`db/versions_migrate/`); every migration command must run for both databases.
- **`eval`-based extensibility.** `Hook#run` and `Report#run` both `eval` user-authored Ruby; `Page` with `dynamic: true` evaluates content as ERB against the view binding. `CanBeHooked` fires after create/update/destroy keyed on `"<table_name> - <event>"`.
- **Background jobs and the one scheduled task.** Solid Queue in-process. Jobs: `SendEmailJob`, `DeliverInfodumpJob`, `GenerateNotificationsJob`, `FinalizeGatewaySetupJob`, `ProcessGatewayWebhookJob`. The only recurring task is `GenerateNotificationsJob` every 5 minutes; `Infodump.ready?` returns true only inside a 0–4 minute window — the cadence and window are coupled.
- **Gateways self-provision on creation.** `after_create` enqueues `FinalizeGatewaySetupJob`; for Stripe that creates a webhook endpoint pointing at this app and stores the signing secret. Webhook receipt skips auth and CSRF and hands the raw body to a background job.
- **Balance caching.** `Ledger#balance_cents` is denormalized, refreshed by summing finalized, non-failed, top-level entries on save. `LedgerEntry`'s `around_destroy` deletes linked entries/links/taggings then refreshes affected ledgers — deleting one side of a transfer removes the other.
- **Time and timezone handling.** Rails zone is UTC; every request wrapped in `Time.use_zone(Settings[:time_zone])`. Hours round to 3-minute granularity (`(delta/3600 * 20).round / 20.0`). Kiosk punch-outs clamp to period end.
- **Kiosk mechanics.** `TimeKiosk` is an ActiveModel form object; a single route accepts GET/POST/PATCH and dispatches on a `tool` string, replacing `#kiosk-content` via Turbo Stream. Kiosk punches set `created_by = "kiosk"`, short-circuiting the normal permission validation. The kiosk still requires an authenticated session.
- **Permission checks live partly in model validations.** `TimeClockPunch`, `CheckinFieldResponse`, `Relationship` accept a transient `created_by` and validate against the permission enum; `Checkin#check_attributes` silently reverts field responses the actor may not change.
- **Ransack pervasive and gated per model.** Nearly every index is `policy_scope(Model).ransack(params[:q])` with whitelisted attributes/associations.
- **Custom generators and form inputs.** Scaffold generator also emits a Pundit policy and Gretel breadcrumb; custom SimpleForm inputs for currency, datetime, color picker, icon picker, remote combobox (`app/inputs/`).
- **Deriving "manager" is expensive.** Tree walks (`all_team_ids`, `all_descendants`, `all_ancestors`) happen in Ruby per request; a re-implementer should expect recursive CTEs or a closure table instead.
- **Testing and quality tooling.** Minitest + Capybara/Selenium system tests; RuboCop, erb_lint, Brakeman in CI.
