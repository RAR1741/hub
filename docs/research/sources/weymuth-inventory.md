## Purpose
A parts-catalog and physical-inventory-state tracker for a VEX + RoboCup program at Mercersburg Academy. Students browse a public catalog (`index.html`/`student.html`) of parts with live Available/Storage/Checked-Out/Unclassified counts, and can submit multi-item parts requests. Teachers/admins get inline card controls to reclassify inventory state (e.g. `UNCLASSIFIED → STORAGE/AVAILABLE`), edit part metadata (name, image, retired/unavailable/not-inventoried/study-guide flags), and a request queue to approve/deny/partially-approve student requests. All state-changing writes are funneled through a single authenticated Google Apps Script backend so the public GitHub Pages site itself never touches write credentials.

## Auth & Roles
- Identity comes from the signed-in Google account (`Session.getActiveUser().getEmail()`), restricted to the Mercersburg Google Workspace domain by the Apps Script manifest (`apps-script/appsscript.json`: `"webapp": {"access": "DOMAIN", "executeAs": "USER_DEPLOYING"}`).
- Roles resolved by looking the email up in a `USERS` sheet — `apps-script/Users.gs` (`getInventoryUser_`, `requireTeacherOrAdmin_`). Roles seen: implicit STUDENT (anyone with an active row), `TEACHER`, `ADMIN`. Inactive user rows are rejected.
- No app-level session/password system at all — every write round-trips through Google's own OAuth via the Apps Script web app URL, then bridges the result back to the GitHub Pages origin (`FRONTEND_ORIGIN`/`FRONTEND_URL` constants in `apps-script/Code.gs`) with `postMessage` (`request-queue-bridge.html`) or a `location.replace` redirect carrying query params (`bridge.html`, `request-bridge.html`).
- `configure-backend.html` is a tiny one-time bootstrap page that stores the Apps Script deployment `/exec` URL into `localStorage['roboticsInventoryBackendUrl']` and redirects — i.e. the backend endpoint is swappable per-deployment without touching the main page.

## Data Model
Lives entirely in one Google Sheet (`CONFIG.SPREADSHEET_ID` in `apps-script/Code.gs`), with these sheets referenced by name:
- **USERS** — `UserID, Email, StudentID, FirstName, LastName, Role, Barcode, Active` (`apps-script/Users.gs`).
- **PARTS** — catalog rows keyed by `PartID` (format `P-######`), with `Program` (`VEX`/`RoboCup`), `Active`, `ProductStatus` (Current/Retired), `Unavailable`, `NotInventoried`, `StudyGuide`, `PartName`, `ImageURL`, plus manufacturer/part-number/category fields mirrored into the static `data/inventory-data-*.js` catalog files consumed client-side.
- **INVENTORY** — physical units, one row per (PartID, State, LocationID, HolderID) bucket with a `Quantity`; states are `AVAILABLE | STORAGE | CHECKED_OUT | UNCLASSIFIED | REPAIR | RETIRED` (`apps-script/Inventory.gs balancesFromValues_`). `LocationID`/`HolderID` columns exist but are "intentionally empty" per `apps-script/README.md` — physical room/cabinet/bin assignment is an explicitly deferred next layer.
- **TRANSACTIONS** — an append-only ledger of every inventory move: `TransactionID, Timestamp, UserEmail, StudentID, PartID, Action(=TRANSFER), Quantity, FromState, ToState, FromLocationID, ToLocationID, BeforeQty, AfterQty, Source, Reference, Notes` (`appendTransferTransaction_` in `apps-script/Inventory.gs`).
- **REQUESTS** — one row per (RequestID, PartID) line item: `RequestID, RequestedAt, RequesterEmail, StudentID, Program, PartID, RequestedQty, Status(SUBMITTED/APPROVED/DENIED), ApprovedQty, FulfilledQty, ApproverEmail, DecisionAt, Notes` (`apps-script/requests.gs`).

## Features
- **Public catalog browsing** with search, program tabs (All/RoboCup/VEX), category filter, and live rollup stats (Catalog Parts, Exact Units, Available, Storage, Checked Out, Unclassified) — `index.html`.
- **Per-part detail modal** showing image, manufacturer, part number, category, per-state counts, and a "needs review"/unresolved-quantity badge for rows where a legacy quantity string didn't parse to a clean number — `index.html` (`detailUnresolved`, `NeedsReview` column handling in `apps-script/Inventory.gs`).
- **Inline admin quick-flags on each catalog card**: toggle Retired / Unavailable / Not-Inventoried / Study-Guide directly from the grid, saved via `action=partflag` — `data/inventory-admin-editor.js`, `apps-script/Code.gs setPartFlag_`.
- **Inline part editing**: rename a part (`action=partname`), change its image URL including unwrapping a pasted `=IMAGE("url")` spreadsheet formula (`action=imageurl`), and soft delete/restore a part card (`action=partactive`, blocked if the part still has any inventory units anywhere) — `apps-script/Code.gs setPartName_/setPartImageUrl_/setPartActive_`.
- **Inventory state migration workflow**: `UNCLASSIFIED → STORAGE`, `UNCLASSIFIED → AVAILABLE`, `STORAGE → AVAILABLE`, each requiring (a) a pre-check of available quantity, (b) a confirmation page server-rendered by Apps Script with a one-time nonce, and (c) a locked, ledgered commit — `apps-script/Code.gs` `doGet action=move` + `confirmMoveFromUi`, `apps-script/Inventory.gs moveInventoryState_`. Explicitly framed as "classify state only," with physical location assignment deferred.
- **Student parts-request flow**: pick a program (VEX/RoboCup), add up to 50 distinct parts with quantities (1-999 each), submit; server validates each part is active/not retired/not unavailable/not reference-only and belongs to the chosen program before writing rows — `student.html`, `apps-script/requests.gs submitPartsRequest_`.
- **Teacher/admin request queue**: loads all requests grouped by RequestID with a derived overall status (`SUBMITTED/APPROVED/DENIED/MIXED`), supports whole-request approve/deny (`action=requestdecision`) and per-line-item batched decisions with individually approved quantities (`action=requestdecisions`, up to 250 at once) — `apps-script/requests.gs loadRequestQueue_/decideRequest_/decideRequestItems_`, `data/request-decisions.js`, `data/request-queue.js`.
- **Low-stock warning banner** driven by client-side comparison of available vs. some threshold — `data/low-stock-warning.js` (not read in full, filename/usage strongly implies this).
- Misc UI fix/patch scripts layered on top of the base pages: `data/card-click-fix.js`, `data/delete-card-simple.js`, `data/student-order-fix.js`, `data/request-queue-iframe-fix.js`, `data/request-queue-button-guard.js` — evidence of iterative bug-fixing directly in production via small isolated patch files rather than editing the main bundle.

- **Google Workspace / Google Sheets** as the entire backend datastore and identity provider — no external DB, no third-party auth. `oauthScopes` requested: `spreadsheets`, `userinfo.email` (`apps-script/appsscript.json`).
- **GitHub Pages** as the static frontend host (`weymuth.github.io/Inventory`), decoupled from the backend via the swappable `BACKEND_URL`/`configure-backend.html` mechanism.
- No Slack/Discord/email/calendar or other third-party integrations found.

## Notable Implementation Details
- **Write path funnels through one Apps Script `doGet`/`doPost` dispatcher** keyed by an `action` query param, each action normalizing/validating its own input (regex-checked PartIDs `P-\d{6}`, whitelisted enum states, integer quantity bounds) before touching the sheet — a clean "one gate, many validated actions" shape worth emulating for any lightweight Sheets-backed admin tool.
- **Every balance-changing write takes `LockService.getScriptLock()`** and appends an immutable ledger row before `SpreadsheetApp.flush()`, giving a poor-man's transaction log without a real database (`apps-script/Inventory.gs`, `apps-script/requests.gs`).
- **Nonce-gated confirmation step for inventory moves**: the backend pre-issues a short-lived (`CacheService`, 600s) nonce keyed to the exact requested change, and the actual mutation (`confirmMoveFromUi`) verifies the nonce matches before committing — a lightweight CSRF/double-submit guard for a Google-account-authenticated but browser-driven flow.
- **Cross-origin communication is redirect/`postMessage` based**, not a JSON API: the Apps Script web app returns full HTML pages that either `location.replace` to a GitHub Pages bridge URL with query-string state, or `postMessage` a JSON payload to a specific `FRONTEND_ORIGIN` and `setXFrameOptionsMode(ALLOWALL)` for iframe embedding (`requestQueuePage_`). This is a deliberate workaround for Apps Script web apps not supporting CORS-friendly JSON responses well from a static-site frontend.
- **Catalog data is compiled into static JS files** (`data/inventory-data-1.js` … `-10.js`, some suffixed `-core.js`) rather than fetched at runtime — likely a manual/scripted export step from the PARTS sheet, trading live-ness for a zero-backend-hit page load; ceiling is that the catalog can go stale between exports.
- **Ceiling called out by the maintainers themselves**: `apps-script/README.md` states `LOCATIONS` (physical room/cabinet/drawer/bin) is "intentionally empty" and is the deliberately deferred next layer — this repo only tracks logical state (Available/Storage/Checked-Out/etc.), not physical placement.

## Verdict
Substantive and very actively developed (30 commits visible, all same-day, with iterative patch files showing real production debugging). On-topic for hub's part design/manufacturing tracking and, more thinly, parts-ordering/PO areas — it is a real, working request → approve/deny → ledgered-transfer pipeline, just built for VEX/RoboCup rather than FRC and running on a Google Sheets "database" instead of a real one. Worth catalog attention for the ideas (single-action-gate Apps Script backend, nonce-confirmed state transitions, ledger-of-transactions pattern, deferred-physical-location design note) rather than for direct reuse — no license means recreate, don't copy.
