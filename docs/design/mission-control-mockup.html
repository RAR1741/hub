G · Mockup note — chosen direction (1A + 1D color menus)
How this maps to the token system. This is variation 1A with one addition carried over from 1D: color-coded nav sections. Four new tokens — --hue-overview, --hue-shopfloor, --hue-team, --hue-admin (light + dark values) — join the existing contract, and each sidebar group sets one --grp var so its header, item icons, active tick, faint active tint, and flyout title all pick up that hue from a single place. Everything else is 1A: the same --canvas/--surface/--ink/--hair + status/role tokens, 8px radius, hairline cards, and hover-and-keyboard flyout submenus (.flyout/.rail-fly revealed by :hover/:focus-within, no JS, Tab-reachable) exposing People, Events, and Admin's real children. Red stays the one brand accent; the category hues are accent-level only (icon + tick + faint tint), never filled panels, and both themes keep AA contrast. Also pulled from 1D: role-tinted avatars — student / mentor / admin initials read their existing --role-* token as a soft color-mix() fill plus matching ring (admin stays solid red), so a directory scans by role at a glance with no new tokens. Deliberately left out of this graft: 1D's larger radius, warmer neutrals, and hued progress bar — those stay as 1A had them. Kiosk (section E) is carried forward unchanged; it's slated for its own pass. Fonts ship self-hosted via next/font: Inter (UI) + JetBrains Mono (data).
