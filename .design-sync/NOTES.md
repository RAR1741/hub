# design-sync notes — FRC 1741 Hub

This repo is a **Next.js product app**, not a distributable React design system. Its
design system is **CSS-based**: tokens + a `@layer components` class vocabulary in
`src/app/globals.css`, plus one presentational React component (`Icon`). Scope was
deliberately bounded (user chose "Tokens + a few primitives") to: the tokens/CSS/fonts
+ `Icon` only. The other ~75 components in `src/components/` are app/data-coupled and
intentionally excluded.

## Key build facts

- **`styles.css` comes from `.design-sync/hub.css`**, generated by
  `.design-sync/build-hub-css.mjs` from `globals.css`. globals.css can't ship as-is:
  it `@import "tailwindcss"` (won't resolve in the sandbox) and wraps the vocabulary in
  `@layer` (loses to unlayered sandbox rules). The transform drops the tailwind import,
  unwraps `@layer base/components`, and prepends a Google Fonts `@import` + the
  `--font-display/-body/-mono` vars that `next/font` injects at runtime in the real app.
  **On any globals.css change, regenerate:** `./dev node .design-sync/build-hub-css.mjs`.
- **`cfg.entry` points at `src/components/Icon.tsx`** only to locate `PKG_DIR`: the
  package shape resolves `PKG_DIR` from `--entry` by walking up to the nearest named
  `package.json` (repo root). Without it, the build looks for `node_modules/team-hub`
  (this repo doesn't self-install) and dies ENOENT. There is no `dist/` — this is
  synth-entry mode.
- **Fonts ship via remote `@import`** (Google Fonts, variable weight ranges — the CSS
  uses 650/750/800/850). Validate prints `[FONT_REMOTE]` (informational, expected). No
  `@font-face` files are bundled.
- Build/validate run **in Docker** (host has no Node): `./dev bash -c "node .ds-sync/..."`.
  Container mounts the repo at `/workspaces/hub`; cwd is already the repo root, so use
  repo-relative paths.

## Verification

- **Render check was skipped** (`--no-render-check`): the app container has
  `playwright-core` but no cached Chromium (`~/.cache/ms-playwright` empty), and the user
  chose to eyeball rather than install ~200MB. Previews were **visually verified by hand**
  via a throwaway nginx container (see below) and looked correct in dark theme (tokens
  flip, fonts load, Icon mounts). If a future run wants a machine gate, install the
  Chromium build pinned by `node_modules/playwright-core/browsers.json`.
- **Serving `.review.html` on Windows:** only host port 3000 is mapped (Next dev), and
  the in-container serve binds an unmapped port. Workaround used:
  `MSYS_NO_PATHCONV=1 docker run --rm -d -p 8088:80 -v "C:/Users/Jordan/Documents/Git/hub/ds-bundle:/usr/share/nginx/html:ro" --name ds-review nginx:alpine`
  then open `http://localhost:8088/.review.html`. **`package-build.mjs` rm's+recreates
  `ds-bundle/` every run, which detaches the bind mount** — restart the nginx container
  after each rebuild or it 404s.

## Re-sync risks (watch-list for the next run)

- **hub.css is generated, not hand-maintained.** If `globals.css` changed, regenerate it
  first (command above) or the sync ships stale styles. The transform assumes the only
  `@layer` blocks are `base` and `components` and the only bad import is `tailwindcss` —
  if globals.css grows a new `@import` that must ship, or new `@layer` names, revisit
  `build-hub-css.mjs`.
- **conventions.md is the real payload** (a CSS design system is mostly class vocabulary,
  not components). It enumerates classes/tokens by hand from globals.css — if the class
  vocabulary changes, update `.design-sync/conventions.md` to match, or the design agent
  composes against a stale vocabulary.
- **Component picker shows essentially one card (Icon).** That's expected and honest for
  this repo — the value is `styles.css` + the README/conventions header + guidelines
  (`docs/design/ui-system.md`), not a component gallery.
- **Kiosk classes (`.kiosk*`) are now theme-aware (as of the Mission Control redesign, #213).**
  They used to be committed-dark by design; that's no longer true — they follow light/dark/system
  via the standard `--canvas`/`--surface`/`--ink`/`--muted`/`--hair` tokens like the rest of the
  app. They still keep kiosk-specific large touch targets and a red focus-border treatment. If a
  future change reverts them to fixed-dark, update this note and `docs/design/ui-system.md` /
  `conventions.md` / `DESIGN.md` again to match.
